# Account Statement PDF

PDF is generated by the **Coditium Python report service** and proxied through PMS.

| Item | Value |
|------|--------|
| API docs | Repo root `api.txt` |
| Local Python base URL | `http://127.0.0.1:8000` |
| Zaura GCP report API | `http://127.0.0.1:8000` on the same VM (`coditium-report.service`) |
| Endpoint | `GET /api/reports/account-statement?customerId={CustomerID}` |
| PMS proxy | `GET /Report/AccountStatement?accountNo={CustomerID}` |
| Config | `ReportService` in `appsettings*.json` / systemd env |
| Client | `Services/ReportServiceClient.cs` |

## Why local works but GCP used to fail

Local PMS calls `http://127.0.0.1:8000` where the Python API is running.

GCP previously defaulted to the old host `http://34.131.132.158:8000`, which is unreachable from the Zaura VM, so **Account Report** hung ~60s and failed.

In-process ReportViewer/RDLC **cannot** render PDF on Linux (`usp10.dll`). Prefer the Python service on Ubuntu.

## Zaura production config (systemd)

```
ReportService__BaseUrl=http://127.0.0.1:8000
ReportService__PreferLocalRdlc=false
ReportService__TimeoutSeconds=60
```

Report API unit: `coditium-report.service`  
App path: `/var/www/pmsprint_python_api`

On-screen statement (HTML): `/Customer/AccountStatement/{accountNo}`  
Customer list button: **Account Report** → `/Report/AccountStatement?accountNo={CustomerID}`
